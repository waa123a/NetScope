# 新项目 AI 开发启动清单

> 用途：把 NetScope 的开发经验变成每个新项目都能直接执行的 SOP。
>
> 不是读完就算，而是照着做完。目标不是“多写文档”，而是更早发现根因、更少返工、换模型不丢状态。

---

## 0. 三层使用方式

1. **知识库**：存流程、模板、案例，供新会话检索。
2. **项目根目录**：每个新项目复制四个状态文件，持续更新。
3. **每次会话**：只推进一个任务，留下证据，结束前更新进度。

熟练度来自重复执行，不来自收藏更多提示词。

---

## 1. 立项：30-60 分钟写清楚

- [ ] 一句话目标：谁，在什么场景下，用它完成什么。
- [ ] 3-5 条 P0，不要超过 5 条。
- [ ] 明确不做什么（Non-goals）。
- [ ] 运行形态：源码 / 安装包 / 便携 exe。
- [ ] 数据位置、权限要求、网络边界。
- [ ] 每条验收都能被观察和复现。
- [ ] 列出 3 个主要风险。

产出：`PROJECT.md`

**门禁**：你能说清“不做什么”，并且每条 P0 都有可观察的验收语句。

---

## 2. 方案：先定边界，再写代码

- [ ] 模块边界：每个模块负责什么、不负责什么。
- [ ] 对外契约：API / CLI / 数据结构。
- [ ] 失败模式：非法输入、超时、权限、并发、数据损坏。
- [ ] 测试策略：哪些用单元测试，哪些必须真实运行。
- [ ] 关键决策及替代方案。

产出：`ARCHITECTURE.md`

**门禁**：一个没参与的人只看文档，就知道新功能该改哪个文件、接口会不会变。

---

## 3. 最小闭环：先跑通一条真实路径

推荐顺序：

1. 解析器 + 测试
2. 核心操作原语
3. 任务/状态管理
4. 对外接口
5. 最小界面
6. 真实端到端验证

- [ ] 完成一次真实操作，不是只跑通单元测试。
- [ ] 错误信息可读。
- [ ] 有一条可重复的启动和验证命令。

**门禁**：真实启动、真实操作、真实看到结果。

---

## 4. 界面：覆盖状态，而不是只画页面

- [ ] 信息架构：主操作只有一个。
- [ ] 空、加载、运行、成功、错误、禁用状态。
- [ ] 危险操作二次确认。
- [ ] 键盘可达，焦点可见。
- [ ] 窄屏布局可用。
- [ ] 真实浏览器打开，控制台无错误。

**门禁**：第一次使用的人，不需要额外解释就能完成核心任务。

---

## 5. 功能迭代：每个需求都走六步

- [ ] 复现：步骤、期望、实际、环境。
- [ ] 定位：根因假设 + 最小验证实验。
- [ ] 验收：一句可判断真假的话。
- [ ] 最小改动：不顺手重构，不改公共接口。
- [ ] 双层验证：自动化测试 + 真实流程。
- [ ] 回归：全量测试 + 一个相邻功能。

产出：`TASK_CARD.md` + `TEST_LOG.md`

**门禁**：验收成立，旧功能不回归。

---

## 6. 加固：主动找失败场景

- [ ] 输入上限、非法值、超长内容。
- [ ] 超时、取消、断网、权限不足。
- [ ] 本地服务鉴权、请求体限制、CSP。
- [ ] 持久化原子写入、上限、损坏恢复。
- [ ] 输出编码、CSV/Excel 注入。
- [ ] 隐私：是否外发数据、是否遥测。
- [ ] 让 AI 扮演攻击者，列出 15 个失败场景并实测。

**门禁**：高风险场景都有明确行为；不能修的写进已知限制。

---

## 7. 打包：换台机器也能运行

- [ ] 确定单文件/目录、控制台/无窗口、数据位置。
- [ ] 只读资源从 `_MEIPASS` 读，可写数据放 exe 同级。
- [ ] 构建命令可复现，不依赖旧 spec 的绝对路径。
- [ ] 空目录冷启动。
- [ ] 重启后数据仍在。
- [ ] 退出后无残留进程。
- [ ] 说明未签名和 SmartScreen 提示。

**门禁**：空目录、冷启动、真实操作、重启持久化全部通过。

---

## 8. 交付：成品 + 说明 + 限制

- [ ] 清理测试数据。
- [ ] 写清启动、退出、数据位置、换端口/换配置。
- [ ] 写清已知限制。
- [ ] 写清卸载/回滚方式。
- [ ] 最终汇报只写实际验证过的内容。

---

## 9. 换模型或开新会话

- [ ] 更新 `PROJECT.md`、`ARCHITECTURE.md`、`PROGRESS.md`、`TEST_LOG.md`。
- [ ] 发交接提示词，让新模型先读四个文件。
- [ ] 要求 10 行复述目标、约束、已完成、阻塞、下一步。
- [ ] 只执行“下一步”的第一项。
- [ ] 用一个小任务做 30 分钟校准，再放大任务。

---

## 10. 每个项目结束后的 15 分钟复盘

回答五个问题：

1. 哪个问题耗时最长？它属于数据、界面、环境、语义、打包还是性能问题？
2. 哪条验收写得太模糊，导致返工？
3. 哪次手动验证值得变成自动化测试或检查项？
4. 哪个模板字段从来没用到？删掉它。
5. 这次有哪些做法可以进入个人“模式库”？

产出：3 条以内，写进 `PROGRESS.md` 或自己的 `LESSONS.md`。

**熟练度的标志**：不是写得更快，而是验收写得更准、根因找得更早、同类问题复发更少。

---

## 11. 熟练度进阶路线

| 阶段 | 做法 | 关注指标 |
| --- | --- | --- |
| 第 1 个项目 | 严格照 8 个阶段执行，记录每步耗时 | 能否完整走通 |
| 第 2 个项目 | 合并阶段 2/3，但保留门禁；开始复用模式 | 返工次数是否下降 |
| 第 3 个项目 | 按风险裁剪流程，建立个人模式库 | 同类问题是否不再复发 |
| 持续 | 用第二个模型交叉验收，定期复盘 | 从立项到可用闭环的时间 |

---

## 12. 今天就能做的最小行动

- [ ] 复制 `PROJECT.md`、`ARCHITECTURE.md`、`PROGRESS.md`、`TEST_LOG.md` 到新项目根目录。
- [ ] 用 30 分钟填写 `PROJECT.md`。
- [ ] 发开工提示词，只确认目标、非目标和方案取舍。
- [ ] 当天只做最小闭环，不碰完整 UI 和打包。
- [ ] 结束前更新 `PROGRESS.md`，写下下一步的第一项。

一句话：**新项目不靠记忆启动，靠清单启动；熟练度不靠读，靠每个项目重复一遍。**
